# Automatic Unit Tests

It would appear you can create unit tests (which from the looks of things are
rather basic in scope and only really cover existence) using snakemake.
snakemake uses pytest for its unit tests, which is nice and modern.

I'm having problems with this all though unfortunately. From the verbose logs,
it would appear that the autogenerated unit tests are simply testing files are
the same. It looks like it just uses your current workflow to create expected
files and then from now on you can re-run the tests to see if the workflow
continues to act like it used to (outputs are the same for the same inputs).
This is quite weak and isn't really something I'd actually use in a real repo.
I'd likely just make my own set of tests for each individual rule I've made,
specifically the actual scripts they are using.

The reason why it isn't working in my case is because there is an element of
randomness, which means that the `cmp` command being used to check for file
equivalence is just gonna immediately fail in all downstream files.

This is at least a nice feature that they've tried to add (and I can see it
sometimes removing the boilerplate you'd need to write). I think the best bit
of this is that it would make it very easy to add more tests to your workflow
as you'd already have a nice starting point (with everything setup for you).
